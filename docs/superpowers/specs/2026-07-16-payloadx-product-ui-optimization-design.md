# PayloadX 产品与 UI 整体优化设计

**日期：** 2026-07-16
**范围：** 现有 React 控制台的 UI/UX、响应式、可访问性、前端性能和基础工程质量；不改变 FastAPI 数据模型或 REST 接口。

## 1. 现状与根因

PayloadX 已具备上传、任务、会话、载荷、告警、统计和设置闭环，构建与后端测试可通过。问题不在功能缺失，而在设计系统没有真正贯穿页面：`themes.ts` 写入一套深色变量，实际组件却使用固定的 Tailwind `teal`、`white` 和 `ink` 类，因此七套主题只有预览圆点变化。

移动端 375px 下页面宽度达到 498px。根因是 Dashboard 的 CSS Grid 子项保留默认 `min-width:auto`，内部 `min-w-[480px]` 表格把整张卡片和父网格撑宽。当前移动导航还遗漏“特征分析”，Header 标题固定为“工作台”，导致信息架构在不同页面不一致。生产首包为 706.8 kB，原因是所有路由和 Recharts 页面同步进入入口包。

## 2. 方案选择

采用“石墨侧栏 + 雾白工作区 + 可切换强调色”的专业安全分析工作台。保留当前品牌识别与高信息密度，不改为全暗色大屏；将七套主题收敛为真正生效的强调色方案，而不是维护七套互相分叉的页面皮肤。

设计原则：

- 页面背景使用微暖雾白和低对比网格/光晕，内容卡片保持清晰边界与轻层次。
- 主色、焦点环、导航激活态和图表主色全部来自 CSS 变量；风险/成功/告警色保持语义稳定，不跟随主题变化。
- 8px 间距体系，卡片 18–20px 圆角，按钮和移动端触控目标不小于 44px。
- 标题、数字、正文、说明文字形成明确层级；等宽字体仅用于 IP、端口、时间和载荷。
- 动效只用于导航、按钮、菜单、加载和状态变化，并尊重 `prefers-reduced-motion`。

## 3. 页面与组件设计

### 应用外壳

- 用一份导航配置同时驱动桌面侧栏和移动抽屉，消除菜单遗漏。
- Header 根据当前路由显示模块名和简短上下文；移动端收敛时钟、用户胶囊等次要信息。
- 移动抽屉支持遮罩关闭、Escape 关闭、路由跳转后关闭，并提供明确的按钮可访问名称。
- Footer 使用运行时年份，避免固定 2025。

### Dashboard

- 顶部指标重排为“1 个主指标 + 4 个次指标”的响应式 Bento 网格，避免五张同质卡片。
- 协议分布、告警、任务和载荷保留当前信息，但加强空状态、交互反馈和视觉优先级。
- 所有 Grid 子项显式 `min-w-0`；桌面保留表格，窄屏改为纵向载荷摘要，不让内部表格撑宽页面。

### 列表、详情与设置

- 搜索、筛选、视图切换使用统一控件状态，并补充 `aria-label`、`aria-pressed` 和可见焦点环。
- 表格外层只在自身容器内横向滚动，页面根节点不得横向滚动。
- 详情页加载完成后显示面包屑、摘要、元数据与 Hex/ASCII 标签页；错误态保留重试/返回路径。
- 设置页使用真实 `<label>` 关联输入框，保存过程区分“未保存 / 保存中 / 已保存 / 保存失败”。强调色预览直接改变主按钮、焦点环、导航和图表色。

## 4. 前端架构与数据流

路由组件改用 `React.lazy` 和 `Suspense` 按页加载，`AppShell`、通用 UI 与主题系统留在入口包。页面数据流保持：

`用户交互 → 页面状态 → lib/api.ts → /api/v1 → FastAPI → 页面加载/成功/空/错误状态`

新增纯配置模块承载导航与路由元信息，新增统一表单/状态样式，不引入全局状态库。主题上下文仅保存 `ThemeId`，通过 CSS 变量影响通用设计令牌；Recharts 从同一色板读取颜色。

## 5. 错误处理与安全边界

- 网络失败继续由 `ApiError` 承载 HTTP 状态和服务端详情；页面只显示可理解消息，不输出堆栈或敏感响应。
- 上传继续使用原生 `FormData`，前端校验扩展名、空文件和体积，后端仍是最终可信校验边界。
- 不在前端保存密钥、Token 或上传内容；本次不新增认证与权限假象。
- 交互按钮不得用无语义容器代替；图标按钮必须有可访问名称。

## 6. 性能策略

- 路由级代码分割隔离 Recharts 和详情页面，目标是入口 JS gzip 明显低于当前 208.06 kB，并消除单块 500 kB 警告。
- 删除未被运行代码引用的遗留 Mock 数据与占位页面文件，避免维护噪声。
- 避免为装饰引入图片或第三方动画库；背景和状态效果使用 CSS。

## 7. 验收与测试

- 自动化：新增前端测试框架，先写失败测试覆盖导航完整性、路由标题、强调色变量和 API 错误消息；保持后端 4 个 pytest 通过。
- 静态：`npm run lint` 无警告，`npm run build` 成功且入口不再包含所有页面。
- 浏览器：在 375×812、768×1024、1440×900 检查首页、上传、载荷、详情、设置；根页面 `scrollWidth <= innerWidth`。
- 交互：验证移动菜单、搜索筛选、视图切换、主题切换、加载/空/错误状态、键盘焦点和 Escape 关闭。
- 视觉：桌面与移动端均保持清晰层级、统一间距、无控件裁切、无默认原生未设计状态。

## 8. 非目标

本轮不重写后端、不新增登录鉴权、不修改数据库结构、不实现 PCAPNG 或实时抓包。它们属于产品功能迭代，不应与 UI 质量修复混在同一轮。
