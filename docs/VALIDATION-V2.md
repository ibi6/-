## 3. 问题分级与处理

### P0 — 致命

无。

### P1 — 高优先级（已修复）

| 问题 | 风险 | 修复 |
|------|------|------|
| 会话/载荷先 `LIMIT` 再由 Python 过滤 | 符合条件的旧记录会错误消失 | 所有筛选下推 SQL，在分页前执行 |
| 会话列表逐行查询载荷 ID | N+1 查询随会话数线性放大 | 改为一次批量分组查询 |
| 同一任务可重复启动解析线程 | 重复写入、状态竞争、资源浪费 | 活动任务集合加锁去重，重复请求返回 409 |
| 重解析异常可能泄露 traceback 到可见操作日志 | 暴露本机源码路径与内部实现 | 数据库只保存通用错误，完整堆栈仅进服务端日志 |
| 上传目录存在配置和代码常量分叉 | 文件写入位置与 UI/环境变量不一致 | 统一使用 `Settings.upload_path`，演示种子也遵循配置 |
| 旧设置可保存未实现协议 | UI 和 API 会暗示 MQTT/FTP 等已实现 | v1.0 协议枚举收紧，旧数据库读取时安全过滤 |

### P2 — 中优先级（已修复）

| 问题 | 修复 |
|------|------|
| 仪表盘硬编码“较昨日”趋势 | 无历史时间窗时返回 0，界面改为“当前累计” |
| FastAPI 422 数组直接 JSON 化展示 | 统一提取可读校验消息 |
| 状态、告警级别、ID 和分页边界不完整 | 枚举、正整数与范围校验统一返回 422 |
| 上传上限在前端固定为 512MB | 捕获页读取后端运行上限并用于校验/文案 |
| 设置页存在未接入解析器的假开关 | 改为真实上传、Hex、存储与固定流水线说明 |
| 帮助页宣称 PCAPNG、Scapy、PostgreSQL 等能力 | 改为当前真实技术栈和路线图边界 |
| 任务详情在完成后仍持续轮询 | 仅活动状态轮询，完成/失败后停止 |
| 移动告警/日志只能横向拖表格 | 375px 使用原生卡片视图，桌面保留表格 |
| 移动协议饼图偶发空白 | 关闭图表入场动画并设置响应容器最小尺寸 |

### P3 — 体验与文档（已修复）

- 提高次要文字对比度，统一三层表面、边框和柔和阴影。
- 手机端任务/载荷/协议/统计指标改为紧凑双列。
- 页头操作在窄屏独立换行，避免视觉裁切。
- 载荷详情消除内容卡片无意义拉伸留白。
- README 顶部徽章从大块堆叠改为克制的 `flat-square` 状态行。
- Banner 去除虚构流量计数，换为状态语义。
- README 加入工作台、流量捕获和 DNS 载荷详情三张真实 1440×900 截图。

## 10. 已知边界

- v1.0 是本地单用户工具，无登录鉴权；不得直接暴露到不可信网络。
- 仅解析经典 PCAP/CAP；PCAPNG 需先通过 Wireshark 转换。
- 无会话密钥时不解密 HTTPS 正文，只展示 TLS 元数据/加密提示。
- 后台解析使用进程内线程；服务重启不会恢复未完成任务。
- 当前没有 Redis/Celery、多用户工作区、MQTT/WebSocket 深度提取或规则插件。
- Docker 配置保留为可选部署示例，但本机未运行 Docker，所有验收证据来自原生流程。
- 性能数据来自小型演示 PCAP；上线前仍应按目标数据规模补充容量测试。
