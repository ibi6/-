# 产品定位 — PayloadX

## 现状判断

| 视角 | 结论 |
|------|------|
| 课程作业 | 部分——最初服务教学演示 |
| 毕业设计 | **是，项目起源** |
| 个人练手 | 部分——解析器有意保持轻量 |
| 开源项目 | **目标形态**——当前包装方向 |
| 商业产品 | **尚未**——缺鉴权、多租户、支持体系 |

**今天的诚实标签：** 具备真实解析链路的 **毕设级产品原型**，正在升级为 **开源网络取证 / 流量分析工具**。

---

## 产品定义

| 维度 | 定义 |
|------|------|
| **名称** | **PayloadX** |
| **一句话** | 开源 PCAP 应用层载荷提取与调查控制台 |
| **品类** | 网络取证 / 流量分析 / 安全运营辅助工具 |
| **定位** | 介于 Wireshark（深度手工）与重型 NPM/NDR（昂贵复杂）之间的轻量 Web 方案 |

### 核心价值

把离线抓包变成 **任务 → 会话 → 载荷 → 告警** 台账：异步解析、多视图检查（结构化 / Hex / 元数据）、现代运维界面，分钟级可安装。

### 目标用户

1. **中小企业 SOC / 网管**——批量 PCAP 初筛，不绑死桌面工具  
2. **安全研究与 CTF**——快速提取 HTTP/DNS 载荷  
3. **教学与学生**——用可运行系统讲清流重组与应用解析  
4. **DevSecOps**——通过 REST 把审包接入自动化  

### 典型场景

- 应急响应：从实验流量中提取登录体 / Token  
- IoT 实验：HTTP 混合流量盘点（可扩展）  
- 课堂教学：五元组聚合 + HTTP 还原演示  
- 工具链：POST PCAP → JSON 载荷  

### 差异化

| 对比对象 | PayloadX 优势 |
|----------|----------------|
| Wireshark | 任务队列、Web 台账、REST、可多人界面路径 |
| Zeek | 安装更轻、载荷优先视图、技术栈易讲清 |
| 商业 NDR | 开源、本地优先、无授权费、解析可改 |
| 纯 Scapy 脚本 | 产品 UI + 持久化 + 告警 + 工程包装 |

### 非目标（v1）

- 无密钥全量 TLS 解密  
- 线速旁路 IDS  
- 多租户 SaaS 计费
