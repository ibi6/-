[Heading 2] 2.1 高频用户故事
[List Bullet] 作为健身小白，我希望回答几个问题后就能获得一周训练计划，这样我不需要自己研究课程。
[List Bullet] 作为减脂用户，我希望拍照后自动识别一餐的大致营养，这样我可以快速记录外食。
[List Bullet] 作为增肌用户，我希望系统根据最近三次训练表现建议加重量，这样我能科学进步。
[List Bullet] 作为忙碌用户，我希望今天状态不好时把训练缩短为 20 分钟，而不是完全放弃。
[List Bullet] 作为用户，我希望看到体重、热量和训练完成度的关系，从而理解结果变化。
[List Bullet] 作为隐私敏感用户，我希望随时导出或删除自己的健康数据。

[Heading 2] 14.3 代码质量规则
[List Bullet] TypeScript strict 开启，不大量使用 any。
[List Bullet] 页面负责组合，复杂业务逻辑放入 hook/service/store。
[List Bullet] 避免超大单文件；超过约 300 行应评估拆分。

[List Bullet] 避免在 JSX 中创建大量常量对象和内联复杂函数。
[List Bullet] 所有异步流程处理 loading、error 和 retry。
[List Bullet] 删除未使用代码和无意义 TODO。
[Heading 2] 14.4 图片资源规则
[List Bullet] 训练人物和肌群图可以使用本地占位资源或合法授权资源。

[List Bullet] 图片使用合适尺寸，避免加载超大原图造成内存压力。
[List Bullet] 不要把远程不稳定链接作为关键 UI 唯一资源。

[Normal] 【角色与任务】
[Normal] 你是一名资深移动端产品工程师、React Native 架构师和 UI/UX 实现专家。请直接开发一款完整的“AI 健身管理 + 饮食管理”移动端 App，项目暂定名为 FitAI。
[Normal] 不要只输出设计方案、伪代码或零散代码片段。你必须直接检查当前项目、创建或修改文件、安装必要依赖、运行质量检查并修复错误，最终交付一个可以安装、启动、演示和继续迭代的完整工程。
[Normal] 【需求基准】
[Normal] 项目根目录中的《FitAI_健身饮食管理App_Codex开发执行书_最终版.docx》是唯一需求基准。先完整阅读文档，特别关注嵌入的 UI 图片、六个核心页面、数据模型、状态管理、实施阶段和验收标准。如果文档与现有代码冲突，优先保留合理的已有能力，并调整代码以满足文档需求。
[Normal] 【技术栈】
[Normal] 必须使用 React Native、Expo、TypeScript、Expo Router、Zustand、React Hook Form、Zod、AsyncStorage、React Native Reanimated、React Native Gesture Handler、React Native SVG、Expo Linear Gradient、Expo Image、Expo Haptics，以及稳定的 React Native 图表库。配置 ESLint、Prettier 和 TypeScript strict。优先选择稳定、清晰和易维护的实现，不要为炫技引入大量依赖。
[Normal] 【运行与质量命令】
[Normal] 项目必须支持 iOS、Android、Expo Go 和本地开发。必须提供并通过：

npx expo start
npm run lint
npm run typecheck
